# ADR-001：采用独立绿地仓库

- 状态：Accepted
- 日期：2026-08-13

## 背景

目标是保留旧项目完整能力，同时从 LangChain/LangGraph 和清晰领域 Module 的角度重建架构。
先复制旧仓库再渐进替换会让新仓库继承旧历史、目录和耦合，不符合用户要求。

## 决策

`haonanhu02-jpg/rag` 从空仓库开始，具有独立 Git 历史、包名、Schema 和目录。旧仓库只作为固定
commit 的行为参考和兼容 oracle。生产代码不得依赖、导入、fallback 到旧项目，也不长期双写。

少量旧代码只有通过逐文件许可、架构、质量和测试评审后才可进入新仓库，并登记来源。

## 后果

- 优点：架构干净、依赖方向可强制、历史清晰，不会把临时迁移骨架变成永久负担。
- 代价：早期没有完整可运行能力，每项能力都必须重新实现和重新取证。
- 风险控制：R0 黑盒兼容 Harness、逐 CAP 报告、R2 起竖切交付、R10 离线数据迁移演练。

## 明确排除

- 不复制旧仓库作为新仓库初始提交。
- 不使用 git subtree/submodule 让新运行时依赖旧项目。
- 不实现 legacy/shadow/canary 代码路由；需要对照时由测试 Harness 分别运行两个系统。
